Endpoint coverage

Every pinned Orca and T3 endpoint, registered RCA HTTP route, service method and executor action in the catalog runs. Select an endpoint to inspect its calls. Catalog probes dispatch a schema fixture or a minimal input through a test host with scripted dependencies. Accepted streams measure the opening dispatch. Refusals and HTTP errors measure that response path. RCA service probes use empty parameters. RCA HTTP probes send empty JSON without credentials and exercise the wildcard gateway with POST. Executor probes verify the requested action against a recording executor. The seven third-party Orca requests originate on the phone.

Per-API regression checks

Each catalog workload runs five times. CI compares the median duration to the first passing run on the same profile with identical outcomes. The limit allows 50% or 5 ms of growth, whichever is larger. The first run establishes the reference.

Operation timings

Percentiles are nearest-rank milliseconds within one run. Only repeated workload operations have a CI limit. The history records the whole run’s verdict, including test failures.

Individual calls and spans

Each row is one recorded invocation at the named layer. A request can produce client, server and executor spans. An empty outcome means that instrumentation did not record one. Search a trace ID to inspect its related spans.

CLI call sites

Shared clients can issue the same HTTP verb or launch the same external tool from different commands. Each row groups calls from one recorded source location in one run.
