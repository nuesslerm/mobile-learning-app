# Agent configuration (skills, hooks, MCP tiers, context)

Loaded on demand when working under `.agents/`. The always-on rules live in `.agents/instructions/root.md`; this file carries the how-to for this area, moved here verbatim so the root stays small (known-gaps #51).

## Generated agent config

`clis/agent-config-sync` (`pnpm run sync:agent-config`, also every SessionStart) renders the `.agents/` contract into real files, never symlinks:
- Contract (zod-validated): `config/sources.json` (instruction dir, command/skill sources, setup script), `config/{hooks,permissions,mcps,plugins,claude-settings}.json`, `instructions/<area>.md` (`root.md` = repo root), `commands/*.md`, `skills/<name>/SKILL.md`.
- Every instruction source becomes `<area>/AGENTS.md` (Codex, opencode) and `<area>/CLAUDE.md` (Claude Code).
- Claude: `.claude/settings.json`, `.claude/{skills,commands}/`, `.claude/setup.sh`, `.mcp.json`. Codex: `.codex/{config.toml,hooks.json,execpolicy/project.rules}`; it reads `.agents/skills/` natively, so skills sourced elsewhere are copied in. opencode: `opencode.json`, `.opencode/{hooks.json,commands/}`; skills from `.agents/skills/`.
- `pnpm run sync:check` (lefthook post-land) fails on any drifted, stale or symlinked output; generated files carry a header where the format allows comments.
- Bootstrap: `.agents/setup.sh` (tool-agnostic). Claude runs it via the SessionStart hook (`.agents/hooks/session-setup.sh`); Codex cloud: set the environment's setup script to `bash .agents/setup.sh`.
- Skills from `skills-lock.json` restore with `pnpm run skills:install` (overwrites local edits; workflow in `.agents/commands/install-skills.md`).

## Adding hooks

Add hooks to `.agents/config/hooks.json`, permissions to `.agents/config/permissions.json`, plugins to `.agents/config/plugins.json`, then `pnpm run sync:agent-config`.

**Reducing manual approval prompts.** `claude.permissions.allow` in `.agents/config/permissions.json` is a living list, not a one-time setup. Every time a human has to manually approve a **Bash command** mid-session that was safe to run, add a `Bash(<tool>:*)` prefix entry and run `pnpm run sync:agent-config` before ending the turn. Never add a manual entry that would defeat `shared.deny` (`gh pr merge`, pushes to `main`/`master`, `LEFTHOOK=0`) — those stay hard-blocked via `claude.includeShared: true` regardless of how broad `allow` gets.

**MCP tool permissions are fully automatic — never add an `mcp__*` line to `permissions.json` by hand.** Three tiers:
- **Repo-declared servers** (`.agents/config/mcps.json`, e.g. `agentation`) get full access, auto-added as `mcp__<server>` (`deriveMcpServerAllowEntries` in `clis/agent-config-sync`) — add a server there and it's trusted on the next sync, no `permissions.json` edit.
- **`FIRST_PARTY_TRUSTED_SERVERS`** (`clis/agent-config-sync/src-rs/contract.rs`: `Claude_Code_Remote`, `github`, `ccd_session`, `Claude_Docs`) also get full access. These are Claude Code Remote's own infrastructure, not opt-in account connectors — confirmed absent from `ListConnectors`' org connector list (which does list Notion/Slack/Linear/Miro/Google Drive) — and they have no repo-side spawn command, so they can't be declared in `mcps.json` the normal way. This is a small, reviewed, deliberate exception list; it is not the place to re-add a connector just because a session happens to use it.
- **Every other MCP server** (real opt-in account connectors — Notion, Slack, Linear, Miro, Google Drive, and any future one) is read-only by a PreToolUse hook (matcher `mcp__.*`, `clis/agent-config-sync/src-rs/guard.rs`, wired via `wf agent-config mcp-guard`): a tool name that looks read-shaped (`get_`/`list_`/`search_`/`read_`/`fetch_`/… ) is auto-allowed, anything else is denied with a reason. This can't be expressed as a static `permissions.json` rule — Claude Code's `deny`/`ask` rules accept a full server wildcard (`mcp__*`) but always win over a more specific `allow`, and `allow` rules can't span servers via wildcard — so a hook is the only way to say "trust these, read-only for everyone else" without naming every non-trusted connector.
- The read/write split is a naming-convention heuristic (fails closed on an unfamiliar verb), not a semantic one — MCP has no "this mutates" flag Claude Code's permissions consult. If a real opt-in connector needs full access, it either becomes a genuinely reviewed addition to `FIRST_PARTY_TRUSTED_SERVERS`, or (if it's repo-spawnable) a real server in `mcps.json` — there's no other place to grant it.
- Covered by `clis/agent-config-sync/tests/flow.rs` (drives the real guard over stdin/stdout for every tier; no real MCP tool is ever called).

## Context management

**Token budget** (1M window — trigger compaction at 700K used):

| Category | Budget | Rule |
|---|---|---|
| System prompt + AGENTS.md | ~15K | Static — never grows |
| Tool definitions | ~10K | Static |
| Message history | ~400K | Compress old turns first |
| Tool outputs | ~200K | Mask after 3+ turns (see below) |
| Working files | ~75K | Evict after use |
| Reserve | 300K | Buffer for bursts |

**Observation masking** — after a Bash output has served its purpose (you've read it and acted on
it), replace it in your mental model with a compact reference. The PostToolUse hook saves outputs
>1.5KB to `.agents/tmp/bash-<id>.md` automatically and injects the path into context. On
subsequent turns, reference the file — don't re-include the full output.

Pattern: `[Obs saved to .agents/tmp/bash-abc123.md. Key: first 200 chars… Use Read with offset/limit.]`

**Scratch pad** — for any output you generate yourself that is too large for inline context:
write to `.agents/tmp/<topic>-<date>.md`, return a 1-line summary + path. Read back with line
ranges or grep. Never re-read the whole file.

**Context partitioning** — spawn parallel subagents when a task exceeds 60% of the window budget
or decomposes into ≥3 independent subtasks. Give each subagent only the context it needs — not the
full session history. Cross-agent handoffs go in `.context/attachments/<id>/` (see `.context/README.md`).

**Session handoff** — when context exceeds 70% or a session is ending for another agent to resume,
run `/handoff` to generate a structured summary in `.agents/tmp/handoff.md`. The next session
reads that file at start instead of re-deriving everything.

## Project opencode agents

`.opencode/agents/{implementer,researcher,reviewer}.md` are source files (not generated, not symlinked: opencode 1.18 does not read a symlinked `agents/` dir). Each pins `mode: subagent`, `model: minimax/MiniMax-M3` (deepseek-v4.1-flash is the fall-through when minimax is exhausted, decision 34), a `steps` budget and a `permission` map (implementer edits and runs commands; researcher and reviewer are read-only). Reach them with `wf offload ask --agent <name> …`; `opencode agent list` must show all three after an edit. `opencode run --model` overrides the agent's pin, so the harness rotation would hand a pinned agent to another provider on a timeout; a caller passes `opencodeDispatch({ models: [<the pinned model>] })` to keep the pin (decision 27). A read-only agent cannot write files: the document it produces is its final message, which the caller saves (decision 28).

## Spawning Claude Code Remote sessions

When an agent working in this repo spins up a new Claude Code Remote session here (`create_session`, or any equivalent), always target the **"No holds barred"** environment — never let it inherit whatever environment the calling session happens to be running in. Look it up by name via `list_environments` if its `environment_id` isn't already in context (do not hardcode/guess the id, it can change). This repo's real ops work (secret rotation, VM management, anything touching `clis/secrets`' write-capable Bitwarden credential) routinely needs access the caller's own environment may not have — spawning into the wrong environment silently strands the child session without it, exactly as happened before this rule was added.
