# Leetcode foundation: what the code does today

A read-only map of `frontend/mla-tamagui/features/leetcode` and the services behind it, taken 20 Nov 2026 at `dev` `91fe1f32`, to ground the plan in the tracking issue. Each area lists the gaps, risks and ideas the mappers found; the issue holds the decisions and the order.

## Code editor: CodeMirror 6 WebView, native-WebView bridge, keyboard toolbar rails, toolbar configura…

The editor is CodeMirror 6 running inside a react-native-webview, loaded from a static HTML string that inlines a 486 KB esbuild IIFE bundle (cm6Bundle.ts, generated from cm6Bundle.src.ts by scripts/cm6-bundle.mjs) and driven by a JSON postMessage protocol. Native React state (ProblemEditorScreen's editorText/editorSelection) mirrors the WebView's text and selection. Two rails above the soft keyboard (SyntaxToolbar plus ActionToolbar) run mostly pure TypeScript text transforms in editing.ts, then write the whole document back with setText plus setSelection. It is a solid Python-first editor with good bracket, indent and undo behaviour, but it is a thin CodeMirror setup. It has no autocomple…

**Gaps**

- Language is effectively hard-wired to Python: EditorInput always sends language: 'python', the screen's EditorLanguage is 'python3' | 'javascript', and no @codemirror/lang-javascript dependency exists, so JavaScript code is highl…
- Language is not in a Compartment: createEditor() picks python()/cpp() once and updateConfig's language field is parsed but ignored, so even a correct language prop could not switch live without recreating the editor.
- editing.ts is Python-only: toggleComment uses '# ' and smartNewline keys off a trailing ':', which would be wrong for JavaScript, C++ or Java.
- No autocomplete: @codemirror/autocomplete is used only for closeBrackets, with no autocompletion(), no completion keymap, no snippets, and no language-server or symbol completion.
- No lint or diagnostics, no search/replace (no @codemirror/search), no folding, no active-line highlight (.cm-activeLine is styled transparent but highlightActiveLine is absent), no selection-match highlighting, and no multi-curso…
- drawSelection() is not enabled, so the theme's .cm-selectionBackground and .cm-cursor styles likely never apply; the palette's selection colour is probably ignored in favour of the native selection.
- palettes.ts defines hljs-* class maps that nothing reads: the editor uses oneDark for any dark palette and defaultHighlightStyle otherwise, so Monokai and Solarized change only background, cursor and gutter, not syntax colours.
- useCodeEditorSettingsStore (palette, font size 10-28, word wrap) has no setter callers anywhere in the app and is not persisted, so users cannot change them; there is no pinch-zoom for font size.
