# Mimic plan: one characterization and differential-testing harness

Status: plan, 5 Nov 2026. Evidence: `docs/audits/2026-11-05-mimic-audit.md` (section numbers below cite it as "audit §n"). It serves `docs/plans/rca-parity/plan.md` sections 4 and 5 and does not change their done-when; it changes how reference behaviour is recorded and replayed. Every count here is from the audit and is re-measured by the milestone that touches it.

## 1. Goal and done-when

`mimic` is one generic tool for characterization (golden-master) and differential testing. A **target** (a CLI, a library function, a WebSocket or HTTP server, a stdio process) is wrapped by a thin **driver**. Mimic:

1. **records** input to output plus side effects from a pinned **reference** as normalised **cassettes**, stamped with provenance (pin, driver, tool versions, seed, rules hash);
2. **generates** inputs (corpus, schema-derived, seeded property-based, later coverage-guided);
3. **replays** the cassettes against our **candidate** as black-box differential tests, diffed under declared normalisation rules and an allowlist of known divergences;
4. **verifies** that cassettes are fresh (pin, rules, corpus hashes) and, when the reference is reachable, that a re-record still equals the committed cassette;
5. **emits evidence rows** that `wf parity coverage` ingests, so a row counts as served only when the chain call was ok and the differential against the reference was clean.

It is surfaced as `wf mimic record | replay | diff | verify` (plus `import`, migration only), agent-first stable JSON, never prompts, failures carry evidence and the next step.

**Done when:**
- No hand-run generator remains for a reference: both Orca `generate.mjs`, `generate-dsl.ts` and the recorder, normaliser, differ and mock of `tooling/t3-conformance` are deleted (its pin, allowlist and goldens stay), and each consumer replays mimic cassettes (X1, X2, X5).
- The TS and Rust normalisers and differs are one implementation (X5); the two `Exchange::masked` copies are mimic mask rules (X4).
- Every cassette carries machine-checked provenance; `wf check --staged` fails when a cassette's recorded pin hash differs from the current pin file (X2).
- `exec-testkit` recordings and `exec-hosted` fixtures are cassettes with an explicit `authored`, `recorded` or `imported` kind; no cassette claims `recorded` without a pinned CLI version (X3).
- `wf parity coverage` reads mimic evidence without absolute or scratch trace paths (X2).
- The orcad oracle is a mimic target pair, not bespoke code (X6).
- Mimic has its own flow tests through its thin binary against a toy reference, and a published run bundle per CI run (section 7).
- Decisions on harness goldens and the other "keep" items are recorded (X7).

**Non-goals.** Pixel and screenshot goldens (`harness-core/src/golden.rs`, flow, runbook goldens) stay: they compare the app with its own past render, not a reference (audit §2.4). Self-snapshots with no reference (`agent-config-sync`, deploy and vm-ops-api scripts) stay or move to a snapshot library one day, never to mimic. Mimic does not run the reference's own test suites and does not replace `Tap`/`trace.rs` method-hit tracing; it reuses them.

## 2. Architecture

### 2.1 Shape: one hexagon, two crates

Ports and adapters per `docs/solutions/architecture/hexagonal-architecture-by-package-type.md`, package type 3 (hexagonal CLI: crates along seams, ports in the crate that owns them, the I/O modules of the crate are the driven adapters, the thin crate is the composition root), copied from `clis/parity` (`parity` + `parity/core`; its `Tree`, `History`, `Traces` adapters sit in the thin crate, `src/adapters.rs`). The `core`/`rs` pair of the doc is the Rust-service shape (type 1) and does not apply; a separate `mimic/rs` crate is created only if link weight or a consumer's dependency needs it (section 3, risk table).

```
clis/mimic/core   (mimic-core)   pure: no I/O. Domain + ports + their doubles behind feature `testing` (the owner of a port ships its double).
clis/mimic        (mimic)        lib + thin bin: `src/adapters/` (stores, drivers, proxies, provisioners), `src/verbs.rs` (JSON output), composition root. Linked into `wf`. Also `src/bin/mimic-toy.rs` (the toy reference, section 4) behind feature `testing`.
tooling/mimic-drivers            ONE pnpm package (the `tooling/*` glob of `pnpm-workspace.yaml:21` matches one level; `t3-conformance` is one too): reference-side drivers in TS, one folder per target under `src/` (see 2.5). Its `package.json` pins esbuild, zod, tweetnacl, noble exactly.
```

**Domain in `mimic-core`:** `Cassette`, `Interaction`, `Step`, `Effect`, `Provenance`, `RuleSet` (masks), `Allowlist`, `Differ` and `Severity` (`none | drift | breaking`, kept from `live.ts`), `Verdict`, `Evidence`, `CorpusSpec`, `Generator` strategies, hashing.

**Ports (owned by core):**

| Port | Role | Adapters (`mimic/src/adapters/`) | Double (`mimic-core` feature `testing`) |
|---|---|---|---|
| `Store` | read and write cassette sets, raw sidecars | `FsStore` | `MemStore` |
| `Driver` | run one interaction against a target and return the observed steps and effects; speaks `mimic-driver/1` | `StdioDriver` (JSON lines to a child process), `NodeFnDriver`, `WsDriver`, `HttpDriver`, `ArgvDriver`, `InProcessDriver` (Rust closure, for crypto/DSL ports) | `ScriptedDriver` (canned steps), `ToyDriver` |
| `Wire` | a tap on a byte or frame stream (record side) | `Tap` (raw reverse proxy from `proxy.ts`+`wsframe.ts`, the frame parser and `WireEvent`-to-step rules live in core `wire.rs`; `Carry::Http`/`Carry::Ws` are the `HttpTap`/`WsTap` of X5; built 6 Nov 2026) | `FakeWire` |
| `Provisioner` | materialise a pinned reference (download + sha256, checkout at commit, `pnpm install --frozen-lockfile`) | `T3Release` (from `pin.ts`), `GitCheckout` (references/), `Npm` | `FakeProvisioner` |
| `Pins` | read a pin file and hash it | `FsPins` | in memory |
| `Clock`, `Rng` | injected time and seeded randomness | system and seeded PRNG | fixed |
| `Evidence sink` | write `report.json` and `trace.json` | `RunDirSink` (to `$WF_TEST_OUTPUT_DIR/<suite>/`) | in memory |

`mimic-core` obeys `cargo_deps.rs` purity (`does-io` ast-grep globs); I/O crates are separate. `mimic` ships no consumer dependency; consumers depend on `mimic` (or `mimic-core` plus an `InProcessDriver`) only as a **dev-dependency**, so no service Dockerfile changes (audit §5).

### 2.2 Cassette format (`mimic-cassette/1`)

A **cassette set** is a directory, one per target-and-scenario family, e.g. `clis/orca-serve/cassettes/mobile-bundle/`:

```
cassette.json        header (one object): schema, provenance, rules ref + hash, corpus ref + hash, interaction count, content hash
rules.json           mimic-rules/1 (or a shared path, see "Normalisation")
corpus.json          mimic-corpus/1 spec when inputs are generated (generator names, seed, counts)
interactions.jsonl   one interaction per line (stable key order, so diffs are line diffs)
raw/                 NOT committed (gitignored): un-normalised capture so rules can be revised and re-applied without re-recording
```

Interaction (one JSON line):

```
{ "id": "<stable case id>", "row": "rpc:orchestration.getSnapshot",   // optional parity row key, same vocabulary as decisions files
  "input": { ... },                          // what the driver was given (seed, call args, argv, script)
  "steps": [ { "dir": "c2s|s2c|call|ret|stdin|stdout|stderr", "channel": "...", "kind": "text|binary|json|exit", "payload": ... } ],
  "effects": [ { "type": "fs.write|spawn|env|net", ... } ],     // side effects observed
  "outcome": { "status": "ok|error", "code": "...", "reference_accepts": true|null }, "tags": [] }
```

Binary payloads are base64 with a `len`; frame order is by direction plus request id so racy interleaving cannot flake a diff (`live.ts:90` convention).

**Provenance (header, all machine-checked):**

```
"provenance": {
  "kind": "recorded | authored | imported | derived",
  "target":  { "name": "orca", "version": "1.4.214", "commit": "dc7cd7be...", "pin_file": "tooling/orca-conformance/orca-pin.json", "pin_hash": "sha256:..." },
  "driver":  { "name": "node-fn", "version": "1", "protocol": "mimic-driver/1", "toolchain_lock_hash": "sha256:..." },
  "tool":    { "mimic": "<semver>", "git": "<sha>" },
  "seed": 12345, "rules_hash": "sha256:...", "corpus_hash": "sha256:...",
  "recorded_at": "2026-11-05T00:00:00Z",   // informational, excluded from the content hash
  "recorded_on": "vm|sandbox|owner-paired", "source": "human-readable note"
}
```

- `recorded`: produced by `wf mimic record` against a pinned reference. `authored`: written by a person or agent (documented-format streams, our own contract exchanges), carries no `pin_hash`, can never satisfy a parity row on its own. `imported`: converted from a legacy file by `wf mimic import`, keeps `source` and the legacy path. `derived`: computed from other cassettes.
- The pin hash is the sha256 of the pin file bytes (for `t3-pin.json`, `orca-pin.json`); for an in-repo reference with no pin (voice-edit-dsl) it is the git tree hash of the declared source paths.
- Version bumps: `mimic-cassette/N` is read by the current tool and the previous one; `wf mimic import --upgrade` rewrites.

### 2.3 Normalisation and non-determinism

Rules are **data** (`mimic-rules/1`), lifted from `tooling/t3-conformance/src/normalize.ts` so there is one dialect (audit §4.1):

| Rule kind | Effect | Source precedent |
|---|---|---|
| `uuid-ordinal` | UUIDs become `<uuid:N>` by order of first appearance | `normalize.ts` |
| `timestamp` | ISO 8601 and epoch-ms by key become `<ts>` | `normalize.ts`, `<ts>` in `siblings_json` |
| `token` | regex-masked signed tokens, tickets, csrf | `normalize.ts` |
| `secret-key` | keys learned as secrets (`access_token`, `ticket`) replaced everywhere they appear | `SECRET_KEYS` |
| `sequence` / `volatile-number` | masks `sequence`, `pid`, `fiberId`, `expires_in` | `SEQUENCE_KEYS`, `VOLATILE_NUMBER_KEYS` |
| `drop-header` | removes `date`, `host`, `etag`, ... (one list; today TS drops 18 and Rust 7) | `DROPPED_HEADERS` |
| `path` | `<placeholder>=<abs path>` | `--path` flag, `<world>`, `<helper:name>` |
| `pointer` | JSON-pointer masks per interaction (`volatile`) | agent-api `volatile`, `VOLATILE = "<volatile>"` |
| `seeded` | a declared input the driver is given instead of randomness (fixed keys and nonces) | G2 `fill(0x11)` etc. |

Allowlist (`ignored`, `omitted`, `shapeOnly`; each entry `path`, `reason`, `phase`) keeps the existing `allowlist.json` format byte-compatible so the T3 file moves unchanged; mimic adds an optional `pin_hash` so a divergence entry expires when the pin moves.

Determinism rules: time, randomness and ports reach the target only through the driver (`Clock`, `Rng`, and `$PORT` allocation by the driver); mimic never depends on wall-clock ordering; the content hash excludes `recorded_at`. A cassette whose re-record differs after masking is reported as `nondeterministic` with the interaction ids, never silently passed. Un-maskable non-determinism (model text) is handled by `authored`/record-once-and-replay only, flagged `replay-only`.

### 2.4 Input generation (`mimic-corpus/1`)

Generated inputs are **stored in the cassette**; replay never regenerates, so replay is deterministic and offline. Generators run only at record time and are named in `corpus.json` with a seed and count.

| Strategy | What it does | First customer | Milestone |
|---|---|---|---|
| `corpus` | inputs from checked-in files or a directory (hand-picked, e.g. the 5 key/nonce triples of G2, the phase-1 session script) | G2, G4 | X1 |
| `seeded` | deterministic PRNG streams (replaces the LCG `0x2f6e2b1` of G3) with named mutators (boundary, truncate, control chars) | G3 (900 + 300 + ... cases), G1 windows | X1/X2 |
| `schema` | derive inputs from a JSON Schema (zod export by the node driver) or from the contract crates' schemas: boundary values, required/optional matrix, invalid-shape probes | Orca `files` namespace spike (15 rows); T3 PR/source-control wire | spike in X5/X6, adopt only if the spike answers audit §3 doubt "are the schemas strict enough" |
| `property` | seeded property-based generation with shrinking when a diff appears (a Rust `proptest`-style adapter behind the `Generator` port); shrunk minimal case is written to the report | G3, crypto | X2 (small), widen later |
| `coverage` | the driver reports covered ids (V8 coverage for node-fn, line counters for Rust); keep inputs that add coverage, store them as `corpus` | none yet | post-X6, only if a customer needs it |

### 2.5 Driver protocol and the TypeScript problem

References are TypeScript (T3, Orca, voice-edit-dsl). **Decision (default, D1):** drivers speak `mimic-driver/1`, JSON lines over stdio (request `{id, op, input}`, reply `{id, steps, effects, outcome}`, plus `hello` returning driver, versions and coverage capability). Rust adapters are in-process or spawn the child; TS drivers live in `tooling/mimic-drivers/*` as a pnpm workspace with a lockfile, so esbuild, zod, tweetnacl and noble hashes are pinned by `pnpm-lock.yaml` and the `toolchain_lock_hash` is stamped in provenance. This kills the scratch-dir `npm i` (audit §4.6). `esbuild` risk, resolved by reading: `pnpm-workspace.yaml:71` sets `esbuild: false` under `allowBuilds`, which only skips its install script; esbuild is already in `pnpm-lock.yaml` (0.27.7 and 0.28.1) and its binary comes from the `@esbuild/<platform>` optional package. `tooling/t3-conformance` already runs TS with no toolchain at all (Node 22.18+ type stripping), so the fallback exists too. X1 still runs the pinned bundle once on the VM (linux-arm64) before any code depends on it; if esbuild fails there, drivers use type stripping plus a node `--import` loader, decided in X1, never by hand-installing into a scratch dir.

### 2.6 CLI verbs and JSON schemas

All verbs: `--json` default output is one JSON object on stdout, schema versioned (`"schema": "mimic-<verb>/1"`), documented in `--help`/`--api`, exit 0 clean, 1 findings, 2 usage or environment error, never prompting. Every failure carries `evidence` (paths: raw capture, expected, actual, diff), `next` (one command), and `warnings`. Spec registered in `docs/reference/wf-cli.md` (a wf flow test compares help text with it).

| Verb | Purpose | Key flags | Output (abridged) |
|---|---|---|---|
| `wf mimic record <set>` | run the reference through the driver over the corpus and write the cassette | `--target <file>` (mimic.toml entry), `--pin <file>`, `--seed`, `--only <id,...>`, `--out`, `--keep-raw` | `{schema:"mimic-record/1", ok, set, interactions:N, provenance:{...}, nondeterministic:[ids], wrote:[paths], next}` |
| `wf mimic replay <set>` | run the cassette's inputs against the candidate and compare | `--candidate <mimic.toml entry>`, `--only`, `--allowlist`, `--suite <name>` | `{schema:"mimic-replay/1", ok, set, candidate, summary:{total,clean,drift,breaking,allowlisted}, results:[{id,row,severity,diffs:[{path,kind:"missing|extra|changed|kind",expected,actual,allowlisted?}]}], evidence:{report,trace}}` |
| `wf mimic diff <a> <b>` | diff two cassettes (reference vs reference after a pin bump; reference vs candidate-recorded) | `--allowlist` | `{schema:"mimic-diff/1", severity, diffs:[...]}` (same diff objects) |
| `wf mimic verify [<set>...]` | freshness and integrity; offline by default | `--live` (re-record into temp and diff against committed; needs the reference), `--staged`, `--all` | `{schema:"mimic-verify/1", ok, sets:[{set, fresh:true, checks:{pin_hash:"ok|stale", rules_hash, corpus_hash, provenance_kind, replay:{...}}, live?:{severity,diffs}}], next}` |
| `wf mimic import <legacy-kind> <path>` | one-time conversion of a legacy fixture (`t3-golden`, `exec-recording`, `exec-hosted`) to a cassette, `kind: imported` | `--out` | `{schema:"mimic-import/1", ...}`. Kept at X7 (see X7 status). |

`replay` also exists as an SDK call (`mimic::replay(&set, &mut candidate)`) so Rust flow tests assert per-case behaviour in-process (the orca-crypto and DSL ports use `InProcessDriver`); the CLI and SDK share the core, so behaviour is identical. Consumer tests are Given/When/Then and derive case lists from the cassette, never copy names.

`mimic.toml` (checked in next to a cassette set) declares targets: `[reference]` driver, command, pin file, env; `[candidate]` driver, command or crate entry; `rules`, `allowlist`. This is data, not a wrapper script (CLAUDE.md: capability lives in a `clis/*` crate surfaced via `wf`).

### 2.7 Evidence output and `wf parity coverage`

`verify` and `replay --suite <name>` write `$WF_TEST_OUTPUT_DIR/<suite>/report.json` (harness run record) and `trace.json` (`method-trace/1`, reusing `exec-testkit` `Suite` writing rules: atomic after every case; run is `error` until complete). Each trace call gains an optional field `"diff": "clean|allowlisted|drift|breaking"` and the interaction's `row` key. Consequences:

- `parity_core::evidence::calls` (`clis/parity/core/src/evidence.rs:45-79`) keeps its current filters and adds one: for a row whose decision says `oracle: mimic`, a call counts only if `diff` is `clean` or `allowlisted` and the cassette's `provenance.kind` is `recorded`. `authored` and `imported` cassettes never serve a row alone. This is a `clis/parity` change owned by X2; `clis/parity` does not depend on mimic (a `Evidence` port in `parity_core` reads the field). `oracle: mimic` is a NEW per-row decision field: `parity_core` has no `oracle` notion today, so X2 adds it to the decisions schema (and its scan tests) before any row uses it.
- The run bundle (`wf test publish`, schema 1) already collects every `trace.json`. Mimic adds a `cassettes` and `diffs` pointer list (an addition like `traces` was); the `deploy.yml` suite glob (`t3-serve-*`, `vm-ops-api-*`, around lines 594-595) gets `wf-mimic-*` and `orca-serve-*` (audit §2.3: the latter is not matched today, so Orca integration traces may not be published; X2 checks the whole step and fixes it).
- Evidence rows stop carrying `/home/user/wt-orca/...` or `.agents/tmp/...` source paths; `source.traces` becomes the bundle URL or run id.

### 2.8 Nx cache and CI

- Replay and offline `verify` are deterministic and CPU-independent: `platform = false`, cached. Declared `[package.metadata.flow] inputs`: the cassette directories, `rules.json`, `allowlist.json`, `mimic.toml`, the pin files, and for in-process candidates the candidate crate's sources (`uses`). A cassette edit reruns the consumer flow task; a pin bump reruns `verify`, which fails stale.
- `verify --live` and `record` are never cached and never part of the normal gate: they need a reference (Node, a downloaded T3 binary, a credential). They run as a manually dispatched job on the VM (a new `mimic-live` workflow input, same pattern as `e2e-tests.yml` `--update-goldens`), publish their run bundle, and open the evidence for the owner. `t3-conformance-live` is replaced by this (X5).
- `wf check --staged` gains `wf mimic verify --staged` (offline, fast): fails on stale pin hash, missing provenance, unknown rules hash, or a cassette changed without its `provenance.tool` updated. It also runs the **no-handrolled-recorder** rule from X1 on (section 8.2).
- Local gate stays lefthook pre-commit; a red hook is fixed, never bypassed.

## 4. Tests and tiers for mimic itself

Per `docs/solutions/testing/verification-ladder.md`; Given/When/Then; behaviour, not implementation; inputs derived from data under test.

| Tier | What | How |
|---|---|---|
| Unit (`mimic-core`) | rule engine (uuid ordinal, secret learning), differ severities, allowlist matching and expiry, content hashing, corpus determinism (same seed, same cases), cassette schema round trip | pure, no doubles |
| Flow (`clis/mimic/tests/flow.rs`, through the thin binary) | every verb end to end against a **toy reference**: a tiny in-repo program (a Rust stdio bin `mimic-toy` with a JSON-lines echo/transform/clock/random/ws mode, so no Node is needed) with a scripted candidate variant. Cases: record writes a cassette whose masks hide ids and timestamps; replay of the same toy is clean; a planted behaviour change makes replay `breaking` naming the JSON path; an extra key is `drift`; an allowlist entry removes it and removing the entry brings it back (planted-break checks, as in `clis/t3-serve/tests/flow/conformance.rs:37,57`); a pin-file edit makes `verify` report `stale` with `next`; nondeterministic toy output is reported `nondeterministic`; `--json` schema stability against the documented schema; no prompt in any path |
| Integration (`tests/integration.rs`) | the built binary as a black box with every dependency faked: WS tap records frames from a toy WS server and replays them to a toy candidate; HTTP proxy; Provisioner doubles (no network) | fakes only, mocked contract tests |
| Browser/Android e2e | not applicable (no UI) | |
| Deployment verification | none (not deployed) | |
| E2E (`cargo-e2e`) | `record` against a real `node` driver over a pinned module in `tooling/mimic-drivers` (the Orca crypto functions) and replay against the Rust port; this is the runbook tier for mimic | CI `cli-e2e-tests` job |
| Parity oracle | `WF_BIN=<full wf> cargo test -p mimic --test flow` through the real router | |

Each CI run publishes a run bundle (`wf test publish`), including a report with the verdict, steps, timings and the diff objects; recordable runs publish a recording per CLAUDE.md. A harness run with no report is not done. **Benchmark (CLAUDE.md rule, D11):** one entry in `docs/audits/2026-11-05-mimic-decision-log` section appended to `docs/audits/2026-09-02-token-diet-decision-log.md`: replay time versus a live record per set, n=1, no model spend; no further runs unless the numbers surprise.

## 5. Migration: milestones X0 to X7

Every milestone ends with: the named old scripts and fixtures deleted (or a stated reason not), each consumer replaying cassettes, `verify` green, the run bundle published, the numbers quoted from `wf mimic` output rather than added by hand, and landed on `dev` (`git fetch origin dev && git rebase origin/dev`, lefthook, push; confirm remote head equals pushed commit before any trunk-tied tier). Never delete branches.

**Completeness guard.** The crawl is compared with the committed catalog of the pinned source (`<app>-methods.json`, from `wf parity coverage`'s own lexer scan: two independent derivations of the same pin, equal on all 304 and all 832 rows). ## 6. How in-flight Orca milestones M6 to M12 record goldens

The parity plan keeps going while mimic is built; the rule has two phases, so Orca work is never blocked.

**Before X1 landed** (historical; X1 landed 5 Nov 2026, and the old generators, `vectors.json` and the pre-mimic recorder table are gone): new vectors go through `wf mimic record` in `tooling/mimic-drivers`, and no "pre-mimic recorders" table in `docs/known-gaps.md` is needed.

**After X1 lands:**
- Every new Orca golden, vector or recorded exchange is recorded with `wf mimic record` into a cassette set with a `mimic.toml`, a pin hash and a seed. Hand-run recorder scripts are forbidden: the **no-handrolled-recorder** check (section 8.2) fails `wf check --staged` on a new `generate*.{mjs,ts,js,py}` or `record*.{mjs,ts}` beside fixtures or goldens, and on a fixture/cassette file without provenance.
- A parity row is `served` on Orca only with a `recorded` cassette replayed clean (or allowlisted with a reason and `pin_hash`) in the latest bundle plus the method-hit trace, as §2.7 specifies.
- M6 to M12 pending rows (41, 49, 18, 26, 20, 59, 59 per audit §3) each name the cassette set they will be recorded into; the milestone's first unit adds the corpus, the second records, the third replays against the candidate.
- Fixtures added before X1 by hand-scripts are re-recorded by `wf mimic import` (`kind: imported`) and then re-recorded `recorded` at the next pin check; they carry no weight as parity evidence until then.

## 7. Risks

| Risk | Likelihood and impact | Mitigation |
|---|---|---|
| Scope too big, never finishes | high, wasted effort | Ordered milestones each deleting something; X1 stands alone and delivers the Orca unlock; stop after any milestone with the old scripts already gone |
| Driver protocol is a leaky abstraction (WS framings, Effect RPC, E2EE) | medium | `Wire` plus `Framing` strategy in core; protocol-specific parts stay in per-target drivers; T3 goes last on the proven core |

| Differ hides real divergence via over-broad allowlists | medium | allowlist entries need `reason`, `phase`, optional `pin_hash`; meta-test "removing an entry fails replay naming it"; every `ignored` path counted in the report |

## 8. Guard rails

### 8.1 Agent-first contract (CLAUDE.md)
Every verb answers in one call with documented JSON, never prompts, carries final state, evidence paths and the next step on failure; humans read the same output. A run that is recordable publishes a recording; every harness run ends with a report; every CI run publishes a bundle.

### 8.2 No-handrolled-recorder check
A `wf check` rule (pipeline crate, `wf check --budget` neighbour) that fails when: a file named `generate*.{mjs,ts,js,py}` or `record*.{mjs,ts}` is added under `**/fixtures/**`, `**/goldens/**`, `**/vectors/**` or `**/cassettes/**`; a file under a cassette directory lacks `cassette.json` provenance; or a `RECORD_*` env switch is added to a test. An allowlist file lists the audit's "keep" items (`extract-tamil-glyphs.ts`, `cm6-bundle.mjs`, capture scripts) so the rule has no false positives. Introduced in X1, tightened as milestones delete.
