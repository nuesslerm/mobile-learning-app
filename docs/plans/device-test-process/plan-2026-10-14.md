## Phase 9 — B9: debugger follow-ups (3 to 5 h)
What exists: browser logpoints (`wf browser debug-set|debug-hits|debug-clear`) and `wf run --debug file:line[:cond]` writing `debug.jsonl` (browser only).
- Source-mapped export for the browser runs (`expo export --platform web --source-maps`, `df` first) so hits carry real file:line stacks.
- Pause and step: `debug-pause`, `debug-resume`, `debug-step` (over/into/out), `debug-eval <expr>` on the paused frame, over CDP (`Debugger.pause`, `resume`, `stepOver`, `evaluateOnCallFrame`), stable JSON per verb.
- Join hits to inputs: each input-log line gets an action id; each hit records the last action id before it.
- Flow tests: `vitest --inspect-brk` driven by the same inspector client (node CDP), so a flow test can stop at a line and report locals.
- Android: Hermes debugging is not built; `wf run --debug` on Android says so plainly and exits non-zero.
- Tests: the same hit-record assertions in the flow, browser and Android harnesses (Android skipped with a plain reason when no device), flow-tested in `clis/wf/tests/flow/browser.rs`.
