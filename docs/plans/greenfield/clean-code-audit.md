# Greenfield clean-code audit (2026-10-05)

> Status 2026-10-21: history. `clis/workflow-cli` was deleted when wf moved to Rust, so the layering described here is not current; wf's target architecture is type 3 in `docs/solutions/architecture/hexagonal-architecture-by-package-type.md`.

This is a read-only audit of `git diff 3974d38d..a166a4e9`, run after the user asked to undo any hacks made to cut line counts. The findings are fixed in three waves (workflow-cli, vm-ops-api, features/agent-config-sync/rca), tracked in progress.md.

Most of this diff isn't golfed or hacky. The domain layers are pure, `wf`'s 4,990-line `cli.ts` was split cleanly into one file per command group, the feature merge is mostly clean renames, and no test was weakened. I found 25 real problems, though. The main golfing case is in the browser-check (visual) and verify code, the worst hacks are in vm-ops-api's shell scripts, and there are two silent-pass paths in the verification code. I read every finding in the code; nothing was edited.

## High

1. **`infra/oracle-cloud/vm-ops-api/src/scripts/devBridge.ts:117-124`** (hack, dead code): the Metro start script uses `sed` to patch `clis/env-bootstrap/bundle/index.js` at runtime. This same diff deletes `clis/env-bootstrap`, so the patch can never match anything. **Fix:** delete lines 117-124.
2. **`clis/workflow-cli/src/worker/data/visualPng.ts:18-28`** (hack, silent pass): `pngjs` and `pixelmatch` are declared dependencies, but they're loaded with a dynamic `import(name)` whose `catch` returns null. Then `visualChecks.ts:98` passes a route whose diff was skipped. A broken install switches off pixel diffing and the tier still reports pass. **Fix:** import both statically; treat a diff that can't be computed as a failure, not a note.
3. **`clis/workflow-cli/src/data/verify/tier3Adapters.ts:74-77`, `worker/data/visualBrowser.ts:37-53`, `worker/data/visualBaselines.ts:46-57`** (hack, copy-paste): three copies of `const SDK_SPECIFIER = '@cli/multi-browser'` plus `await import(SDK_SPECIFIER) as Sdk`, each with its own hand-written type for the SDK. This sidesteps type checking of a dependency the package already declares. **Fix:** one static import in a single shared adapter, using the SDK's real types.
4. **`clis/workflow-cli/src/worker/data/visualServer.ts:6-14`** (golfing): the in-page error collector is hand-minified JavaScript: about 10 statements per line, names like `oe`, `of`, `os`, `w`. **Fix:** put it in a real `.js` asset that is formatted and linted, and read it at startup.
5. **`clis/workflow-cli/src/worker/data/visualBrowser.ts:119-130`** (golfing, copy-paste): `inkInPage` crams 3-5 statements per line with names like `cv`, `d`, `n`, `o`, `k`, `l`, `s`, `sq`. It also re-implements the domain function `inkOf`. **Fix:** decode with pngjs (see 2) and call `inkOf`; drop the in-page copy.
6. **New code ignores the repo's own Prettier config (80 columns), and nothing enforces it in workflow-cli** (golfing). Running Prettier on the new files grows them a lot: `tier3Adapters.ts` 272→446 lines, `deployCommands.ts` 245→350, `commands/verify.ts` 126→200, `tier3.ts` 230→302, `tier3Report.ts` 214→280, `budget.ts` 62→105. In the same diff, vm-ops-api is formatted. workflow-cli was already unformatted before this diff, but the new files go further. Example: `commands/verify.ts:35` is a loop, a filter, a map and a join in one 190-character line. **Fix:** run Prettier on workflow-cli and add `prettier/prettier` to `clis/workflow-cli/eslint.config.mjs`. The line-count budget currently rewards the opposite.

## Medium

7. **`tier1.ts:28`, `tier3Report.ts:100`, `worker/domain/visualChecks.ts:107`** (copy-paste): the same nested-ternary "skip/fail/pass" calculation appears three times (`tier1Of`, `tier3Of`, `tierOf`). `tierOf` also hard-codes `tier: 2`. **Fix:** one `tierOf(tier, items, ms)` in domain, with an if/return chain.
8. **`tier3Adapters.ts:199` with `tier3.ts:31,165-182`** (dead seam): the production `setTesting` always returns `false`, so every run adds a "no busy-flag route" note. Only the test fake implements it. **Fix:** remove the port, or implement it.
9. **`tier3Adapters.ts:223`** (swallowed error): `ociObjectGet(...).catch(() => null)` treats auth and network failures as "no tier record". **Fix:** return null only for not-found; rethrow everything else.
10. **`tier3Adapters.ts:11,15-16`** (layering): the data layer calls use-case logic (`publishRunDir`, `publishEpicIndex`, `replacePrBlock`, `INSTALL_STEP`). **Fix:** the use-case composes these; the adapter only does IO.
11. **`worker/use-cases/worker.ts:3-4`** (layering): the use-case imports `leaseMap` and the concrete types `GitLeases`/`Workspace` from `worker/data`. **Fix:** define the lease-store and workspace ports in `worker/domain/ports.ts` and move `leaseMap` to domain.
12. **`worker/use-cases/worker.ts:114-462`** (size, naming): `runWorker` is one 350-line closure with nested `land`/`pipeline`, and cryptic names (`rb`, `g`, `p`, `c`, `inst`, `base0`). Line 204 gates the rebased tree with `new AbortController().signal`, so stopping can't cancel it. Line 352 detects a lost lease by matching the error text against `/rejected|stale info/`. **Fix:** split it into `landUnit`/`runPipeline` functions, pass `r.abort.signal`, and have `renew` return a typed `lost` result.
13. **`entrypoints/deployCommands.ts:59-122`** (business logic in entrypoint): the build → check tag → redeploy flow, its option rules, and its stdout writes live in the Commander file. Lines 55 and 102 use `as` casts where a type guard would do. **Fix:** move it to `use-cases/deploy/run.ts` behind ports.
14. **`vm-ops-api/src/scripts/redeploy.ts:26-50` and `devBridge.ts:45-87`** (hack, copy-paste): Node programs are built up as arrays of string fragments, including `console.error`/`process.exit` and `catch(e){}`. `RESOLVE_BACKEND_LINE` and `RESOLVE_AGENT_LINE` are identical except for the hostname. **Fix:** ship `provision.js` and `resolve-tailnet-host.js` as real files in the image, and pass the hostname as an argument.
15. **`devBridge.ts:173-272`** (copy-paste): the BRANCH/SAFE/APP_DIR/PORT/PIDFILE preamble and the `/proc` kill loop are repeated in each of the start/sync/stop/status/logs scripts. **Fix:** one `preamble()` helper and one `killPort()` helper.
16. **`features/{settings,service-report,dev-tools,coding-agent}/eslint.config.mjs` (~520 lines each) and `vitest.config.ts` (~129 lines each)** (copy-paste): four near-identical copies, differing only in the package name. `features/AGENTS.md` says the package merge was done to stop duplicating config, but these configs are still duplicated. The headers also reference paths that don't exist (`frontend/mobile-learning-app`, `features/agent`, "Task 2's relativizer"). **Fix:** one shared `createFeatureEslintConfig(name)` and a shared vitest preset.
17. **`clis/workflow-cli/src/use-cases/android/prepare.ts`** (dead code kept alive by tests): the `wf prepare android` command and its integration tests were removed, but `androidPrepare` is still only imported by two unit tests. **Fix:** delete it and those tests.
18. **`entrypoints/commands/reportHealth.ts:74-94`** (copy-paste): it re-implements the stdout-to-stderr redirect from `runJsonAware` (`cli.ts:82-94`), including its `as any` and lint-disable. **Fix:** pull out a `withStdoutToStderr(fn)` helper and use it in both places.

## Clean areas
- **Comments and lint escapes:** no `@ts-ignore`, `@ts-expect-error` or `prettier-ignore` added. The `as any` and `as unknown as` casts in workflow-cli entrypoints (`passthroughs.ts:11`, `reportHealth.ts:78`, `logEmitCommand.ts:18`, `cli.ts:85`) are carried over from the old `cli.ts`, not new. Each eslint-disable that was added has a stated reason.
- **Architecture:** domain is pure in `worker/domain` (only `node:path` posix) and `vm-ops-api/src/domain`. The features use proper `exports` maps with no deep imports, and the merge was mostly R095–R100 renames.
- **remote-chat-agent:** `plugins/**` is readable, typed and well-named. There is no `backend/remote-chat-agent/run/` directory; the run code is in `src/cli/run.ts` and `src/use-cases/runOnce.ts`, which I did not audit.
- **Smaller packages:** `libraries/hook-runtime` (`guard.mjs` is dense but has a reason for each branch) and `tooling/cli-bundle` are acceptable. `vm-ops-api` routes check tag and ref before anything reaches `sh -c`.
- **Tests:** the 76 deleted test files go with deleted source (maestro, doctor, vm-jobs, usage, and so on). No `.skip`, and no assertion was loosened to accept either outcome.

The two oversized files, `use-cases/ios/launch.ts` (791 lines) and `use-cases/report/health.ts` (686), were bigger before this diff and shrank in it. They're old debt, not something the merges created.
