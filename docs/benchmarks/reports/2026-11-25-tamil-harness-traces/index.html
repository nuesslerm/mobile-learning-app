Method and provenance

Sample size

Five original controlled iOS pairs, five iOS pairs after instrumentation, five matched Chrome pairs, three screenshots-only Chrome pairs, ten independent driver profiles and three flow runs. The Buoy SDK recorded three pairs on iOS and three in Chrome. Buoy Desktop measured three separate keyboard journeys. The Android table lists each hosted attempt and its outcome.

Workload

Five paired native library → First steps → Practice → Back journeys from the original controlled iOS comparison. The browser comparison follows the same checkpoints. Independent operation traces cover five iOS and five framed browser runs. Three in-process flow samples run eight Tamil lesson tests with golden rendering. Integration suites exercise additional behaviors.

Method

The iOS pair data comes from the original Tamil iOS driver report; its RSS includes device-specific helpers, subtracts idle and samples app RSS independently. Browser pairs alternate driver order and launch fresh drivers. First and final PNG modification times bound startup and journey. Total includes shutdown. Host RSS sums sampled process trees including Chrome and the isolated wf daemon. Shared pages can be counted twice. Browser app RSS is inseparable from these renderer processes. Maestro web required integer-coordinate Back taps on the visible header icon. Both drivers requested recording; Maestro warned that the web recording produced no frames. The output workloads therefore differ. The wf collector stores OTLP span timestamps and parent IDs locally. Maestro command spans come from its recorded command timestamps, exported after process exit. Overlapping spans must not be added together. The headline subtracts the two group medians. The cards take the median of the within-pair differences. Driver internals and app attribution below are interpretations.

Environment

Apple Silicon Mac, tamil iPhone 17 simulator, iOS 27.0, Xcode 27.0. The controlled iOS timing pairs used the installed com.nuesslerm.mla-tamagui 1.0.0 (1) binary. The local case suites and the separate Buoy development-bundle recordings ran in Expo Go 58.0.7. The final paired web workload ran on a local Expo export with the same Chrome for Testing 147.0.7727.117 executable, Maestro 2.6.0 and matching ChromeDriver. wf launched Chrome with --use-mock-keychain, --password-store=basic and --enable-automation, flags also enabled by ChromeDriver. wf rendered its phone shell. Maestro used its standalone web viewport. The five standalone wf browser phase profiles used desktop Chrome 158. The three flow samples used Vitest.
