Method and provenance

Sample size

Five paired attempts, ten successful runs; setup and pilot attempts tabulated separately.

Workload

On the Tamil library, open First steps, open practice, assert the lesson start control, then go back twice and assert First steps is visible. Both flows record video and write the same three screenshots.

Method

Five pairs in alternating order with a fresh CLI for every attempt. Before timing, terminate the app, reopen its Tamil deep link and assert the library control is visible, then settle for two seconds. Preserve app data and keep the same simulator booted. Allow 65 seconds between consecutive Maestro launches at pair boundaries after observing a port-binding failure. Setup and this cooldown are outside the stopwatch. Startup is wall time to the first completed screenshot file, including recording and assertion. Journey is the difference between the final and first screenshot modification times. Total includes driver launch, recording finalization, report creation and process exit, observed by polling. Sample macOS ps RSS for the driver process tree, device-specific idb companions or Maestro simulator runner, and the app separately, sleeping 160 ms between scans. CSV timestamps record the actual cadence. Sum of RSS can double-count shared pages and miss short-lived peaks. Subtract each driver’s pre-launch idle helper baseline for incremental peak. Residual is sampled immediately after exit. Unrelated host load was uncontrolled. Compare medians and paired differences on successful matching pairs only. Failed attempts remain visible with their elapsed time and memory. Pilot runs exposed an occupied Maestro XCTest port and inconsistent initial screens after reusing app navigation state. Pilot and setup-trial measurements are attached separately.

Environment

macOS 27.0.1 arm64; booted simulator tamil, iOS 27.0; com.nuesslerm.mla-tamagui 1.0.0 (1); installed executable SHA-256 6b97d029c967880d0a2a924ac65c0d7b211b71506836420084101b45218e0c91. Maestro 2.6.0; local debug wf binary SHA-256 8ca06bedfb6605c3940b9c8ad06e60a33afce4958f6c5f4a7f76baa6db281070. Pair 1 used the earlier local wf build with SHA-256 4b896b2af566197a5c7a9f53720149862a65571dede5dd6faf547a23ebdcc2e8. The binary was relinked for the report CLI during the pause before pair 2. The iOS driver source and installed application were identical throughout.
