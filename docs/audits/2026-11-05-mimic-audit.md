# Mimic audit: hand-rolled recorders, fixture generators and golden approaches

Status: audit, 5 Nov 2026. Read-only research on `dev`; no builds, no tests, no commits, `wt-orca` untouched. It feeds `docs/plans/mimic/plan.md`.

This merges four independent lenses: **G** (generators and recorders), **F** (fixtures and goldens by family), **T** (tooling to absorb or reuse, Nx/CI/Docker), **R** (reference behaviours the parity programme must reproduce, per target kind). Every claim carries the lens that made it. Counts are from commands unless marked "(header)" or "(plan)". Section 6 lists where the lenses disagree and which number to trust.

## 1. Headline findings

1. **Three programs run a pinned reference once, by hand, and commit what it printed.** `clis/orca-serve/map-mobile/fixtures/generate.mjs`, `clis/orca-serve/crypto/vectors/generate.mjs`, and `backend/remote-chat-agent/rs/tests/golden/generate-dsl.ts` (G, F, T, R agree). None is run by a wf verb, an Nx target or CI. The Orca two need `npm i esbuild zod@4.6.7` (or `tweetnacl@1.0.3 @noble/hashes@1.8.0`) in a scratch dir plus `NODE_PATH`; the versions live only in a header comment, `esbuild: false` in `pnpm-workspace.yaml:71` (`allowBuilds`) only skips its install script (esbuild is in `pnpm-lock.yaml` at 0.27.7 and 0.28.1, root `node_modules/esbuild` exists), and neither script reads `tooling/orca-conformance/orca-pin.json`.
2. **A mimic prototype already exists for T3, in two languages.** `tooling/t3-conformance` (recording proxy, WS framing, normaliser, golden recorder, allowlist, differ, live drift report, a "Not T3" mock; about 2,573 lines with tests) is the most complete precedent. `clis/t3/tests/flow/support/conformance.rs` (379 lines) re-implements the normaliser and differ in Rust, reading the same `allowlist.json`. The two already disagree: the TS side drops 18 headers, the Rust side 7 (T). This is the strongest argument for one core.
3. **Most "recorded" fixtures are not recorded from a reference.** Only the T3 goldens (`goldens/v0.1.6`), the Orca crypto vectors, the Orca bundle manifest replies and `dsl.json` come from running a real reference. The exec-testkit CLI recordings and the exec-hosted gh/glab fixtures are written from documentation (`provenance: documented-format`; gaps `docs/gaps/exec-testkit-recordings-not-from-real-clis.md`, `docs/gaps/exec-hosted-fixtures-not-from-real-clis.md`). The 260-odd agent-api exchange fixtures are authored from our own service and, behind `RECORD_GIT_FIXTURES` / `RECORD_HOSTED_FIXTURES`, can be rewritten from our own output, which can bless a regression silently (F).
4. **No staleness gate anywhere.** Nothing compares a cassette's recorded pin with the current pin. `goldens.json` and `vectors.json` carry only the free text `generatedFrom: 'references/orca @ pinned commit; ...'`; `desktopVersion: '1.4.214'` is hard-coded in the bundle generator (`generate.mjs:40`, a hand copy of `orca-pin.json`). `wf parity coverage` hashes `orca-pin.json` into its own inputs but never regenerates or verifies these files. `dsl.json` can age behind `voice-edit-dsl` and still pass against Rust.
5. **The evidence pipeline is strong but proves the wrong thing for differential parity.** Method-hit traces (`exec-testkit` `Tap` + `trace.rs`, schema `method-trace/1`) and `wf parity coverage` prove a chain test reached rca-service/rca-exec and the wire served the call. They do not say the reply equalled the reference's. Mimic must feed this pipeline, not replace it (T, R).
6. **The largest uncovered reference surface is Orca.** 824 registered methods, 301 parity rows: 11 served, 272 pending, 6 not-offered, 9 excluded, 3 flagged (R, from `orca.json`). `tooling/orca-conformance` holds only the 5-line pin file; the orcad oracle (plan section 5, M5 onward) is plan-only, and is a differential test, which is exactly what mimic is.
7. **Four-plus cassette dialects and four-plus normalisers, none declared as data.** See section 4.

## 2. Inventory: every hand-rolled recorder, generator and golden approach, with disposition

## 4. Cross-cutting findings (evidence for "unify")
